# H3 Clip Plan — file format specification (version 6)

This document is written for both people and language models. It defines the JSON file that
drives the H3 Clip Plan nodes for ComfyUI. A machine-readable version is in
[`plan.schema.json`](plan.schema.json). Two complete examples, with their images and song in the same folder:

- [`../examples/robot_beach.plan.json`](../examples/robot_beach.plan.json): a short instrumental music video (`music_video` mode);
- [`../examples/robot_workshop.plan.json`](../examples/robot_workshop.plan.json): a spoken scene (`free` mode).

## 1. What a plan is

A plan describes one video as an **ordered list of clips** generated by MiniMax H3. For each
clip it says how long it is, whether it continues the previous shot, which references it uses
and what the prompt is.

A plan has one of two **modes**, for the whole project:

| | `music_video` | `free` |
|---|---|---|
| Sound | a song supplied by the user, injected into every clip and kept untouched | generated by H3 with the picture: dialogue, voices, ambience |
| What H3 generates | the picture only, synchronised to the song | picture and sound together |
| Characters' voices | not used (the singing is in the song) | optional voice samples, one per character |
| Spoken / sung words | in the song; the prompt repeats them for lip sync | written in the prompt; H3 speaks them |
| Final soundtrack | the original song | the generated sound of each clip, joined at the same places as the picture |

Background music that does not drive the picture is not part of a plan: add it afterwards in a
video editor.

The plan does **not** contain any start time. Clip positions are computed from the clip lengths
(section 4). Change one length and every later clip moves with it.

A plan contains nothing that depends on the user's machine. It names its references with labels
(`robot`, `beach`); the user attaches a real image to a label in an "H3 Plan - Reference" node, and
a voice sample in an "H3 Plan - Voice" node, both carrying the same name. The picture size is
chosen in the workflow.

## 2. Top-level object

| Key | Type | Required | Default | Meaning |
|---|---|---|---|---|
| `version` | integer | yes | | `6`. (Versions 3 to 5 are still read; versions 1 and 2 are read as `music_video`.) |
| `project` | string | yes | | Short name (letters, digits, `_`, `-`). Output goes to `output/h3_clip_plan/<project>/`. |
| `mode` | `"music_video"` or `"free"` | no | `"music_video"` | See section 1. |
| `clips` | array | yes | | 1 to 64 clip objects, in playing order (section 3). |
| `refs` | object | no | `{}` | Reference name → short description of what the user must supply ("the girl: image and voice", "the father: voice only"). Names use letters, digits, `_` and `-`. If given, every name used by a clip must be declared. Declare them all: the descriptions tell the user which file goes where. |
| `width`, `height` | integer | no | | Fallback picture size, multiples of 32, both or neither. Normally left out: the size connected in the workflow wins. |
| `context_frames` | integer | no | `39` | Frames shared by a clip with the end of the previous one. Keep `39`. In `free` mode only 39, 90, 141, 192 or 243 are allowed (section 4). |
| `crossfade_frames` | integer | no | `0` | `0` = hard cut at every seam. `1` to `context_frames` = linear picture blend over that many frames at every seam. |
| `audio_feather_ticks` | integer | no | `8` | `free` mode only. Length, in 25 ms steps, of the soft release at the end of the sound copied from the previous clip. `8` = 0.2 s. |
| `seed` | integer | no | | Base seed. Clip *i* uses `seed + i`. Without it, each clip gets a stable seed derived from the project name. |
| `ref_image_size` | `"match"` or `"max"` | no | `"match"` | Passed to the H3 reference encoder. |
| `song` | object | `music_video` only | | `file` (string, informational) and `duration_seconds` (number, lets a checker verify that the plan fits in the song). Forbidden in `free` mode. |
| `start_video` | object | no | | Clip 1 continues (or cuts from) a segment of an existing video: section 5.1. |
| `edit_video` | object | no | | `free` mode: every clip edits its slice of a segment of an existing video: section 5.2. Not with `start_video`. |
| `notes` | string | no | | Free text, ignored. |

Keys starting with `_` are ignored everywhere and can hold comments. Any other unknown key
produces a warning.

## 3. Clip object

| Key | Type | Required | Default | Meaning |
|---|---|---|---|---|
| `frames` | integer | yes | | Raw clip length at 24 fps. Must be `17k + 5` and greater than `context_frames`. |
| `prompt` | string | yes | | Complete MiniMax H3 full-reference prompt (section 6). |
| `continue` | boolean | no | `false` | `true`: same shot goes on, the clip starts from the last frames of the previous clip (and, in `free` mode, from its last sound). `false`: new scene, generated from scratch. Must be `false` for the first clip. |
| `refs` | array of strings | no | `[]` | The references the clip uses, images and voices alike. `music_video`: at most 9. `free`: at most 12 in all, of which at most 9 images and 3 voices are actually used. |
| `name` | string | no | `clip_NNN` | Unique label (letters, digits, `_`, `-`), used in file names. |
| `seed` | integer | no | | Overrides the seed for this clip. Change it to get another take. |
| `lyrics` | string | no | | `music_video`, informational: the words newly heard in this clip. |
| `dialogue` | array | no | | `free`: the lines spoken in this clip, each `{"speaker": "<ref name>", "text": "...", "language": "French"}`. Used by the checker only (speaker exists, text present in the prompt, speaking rate); the prompt is what H3 actually says. |
| `notes` | string | no | | Free text, ignored. |

Legal values of `frames` up to about ten seconds:

| frames | seconds | | frames | seconds |
|---|---|---|---|---|
| 56 | 2.333 | | 158 | 6.583 |
| 73 | 3.042 | | 175 | 7.292 |
| 90 | 3.750 | | 192 | 8.000 |
| 107 | 4.458 | | 209 | 8.708 |
| 124 | 5.167 | | 226 | 9.417 |
| 141 | 5.875 | | 243 | 10.125 |

Longer clips are accepted (260, 277, …) but are slow to generate; a checker warns above 243.

## 4. Timing rules

All times are in frames at 24 fps; divide by 24 for seconds. The rules are the same in both modes.

Every clip except the first overlaps the end of the previous clip by `context` frames, where
`context` is the largest value of the form `17k + 5` that is ≤ `context_frames`, ≤ the previous
clip's length and < the clip's own length. With the default settings this is always 39.

```
raw_start[1] = 0                                context[1] = 0
raw_start[i] = raw_start[i-1] + frames[i-1] - context[i]
visible[i]   = raw_start[i] + context[i]        (= end[i-1])
end[i]       = raw_start[i] + frames[i]
```

- `raw_start` is where the clip begins on the timeline (in `music_video` mode, on the song).
- `visible` is the first frame of the clip that reaches the final video. The overlap before it
  is dropped at assembly (or blended, if `crossfade_frames` > 0).
- The final video lasts `end` of the last clip.

Consequences that matter when planning:

1. **A clip shows `frames - 39` new frames**, except the first clip, which shows all of them.
   A 243-frame clip adds 204 frames (8.5 s) to the video.
2. **Cuts fall on a fixed grid.** If the first clip has `17a + 5` frames, every later clip ends
   at `(5 + 17n) / 24` seconds for some integer `n`: 0.208, 0.917, 1.625, … one step every
   0.708 s. A desired cut time `t` snaps to `n = round((24·t − 5) / 17)`.
3. **`music_video`: the last clip must end inside the song**: `end[last] / 24 ≤ song duration`.
4. **A clip with `continue: false` still has an overlap.** Its first 39 frames (1.625 s) are
   generated and then discarded: a hidden lead-in. It should show its scene fully established
   from its very first frame. In `music_video` mode its prompt covers the song from `raw_start`.
   In `free` mode nobody should speak during the lead-in: start the dialogue after it.
5. **`free` mode: the context must fall on the sound grid too.** H3's sound is cut into 25 ms
   steps and a frame lasts 41.7 ms; the two only line up every 3 frames. A `continue` clip copies
   the previous clip's last `context` frames *and* the matching sound, so `context_frames` must be
   both `17k + 5` and a multiple of 3: 39, 90, 141, 192, 243. Use 39.

## 5. `continue`: same shot or new scene

| | `continue: true` | `continue: false` |
|---|---|---|
| Starts from | the last 39 frames of the previous clip, copied exactly (and, in `free` mode, the matching 1.625 s of sound) | nothing |
| Use for | the same shot going on: same place, same framing, same character state | a new place, a new subject, a cut |
| Seam in the final video | invisible, and inaudible in `free` mode | a cut (or a picture blend if `crossfade_frames` > 0) |
| References | should be the same set as the previous clip | free |
| Regeneration | must be rendered again whenever the previous clip is rendered again | independent |

Design intermediate clips so that they end with motion still in progress (a gesture, a camera
move) when the next clip continues them, and let the last clip of a scene resolve.

In `free` mode, **do not end a clip in the middle of a word**: end each clip with a short silence
(about half a second). The next `continue` clip hears the end of the previous one and goes on from
there; it must not repeat lines that were already said.

### 5.1 Starting from an existing video: `start_video`

```json
"start_video": {"ref": "intro", "start": 3.0, "end": 11.0, "in_assembly": true, "song": "with_video"}
```

| Key | Type | Default | Meaning |
|---|---|---|---|
| `ref` | string | | Reference name of the video, declared in `refs`. The file is given by an « H3 Plan - Video » node with that name. |
| `start`, `end` | number (seconds of the file) | `start`: 0 | The segment used. Its length is snapped to the frame grid (17k + 5 frames at 24 fps): `end` is kept, `start` moves forward by less than 0.71 s. It must last more than `context_frames`. |
| `in_assembly` | boolean | `true` | `true`: the segment opens the final video. `false`: it is only a springboard; the final video starts where clip 1 starts (its first frames are the end of the segment, regenerated). |
| `song` | `"with_video"` or `"after_video"` | `"with_video"` | `music_video` mode, segment in the video. `with_video`: the song starts with the segment (the segment loses its own sound), so clip 1 starts later in the song. `after_video`: the segment keeps its own sound and the song starts when clip 1 shows. |

With `start_video`, clip 1 may have `"continue": true`: it starts from the last 39 frames of the
segment (picture, and sound in `free` mode). With `"continue": false` the segment is followed by a
cut. On the timeline the segment takes frames 0 to its length; every clip comes after it.

### 5.2 Editing an existing video: `edit_video`

```json
"edit_video": {"ref": "source", "start": 12.0, "end": 40.0, "sound": "original",
               "instruction": "the footage becomes a hand-drawn cartoon; the man is replaced by {picture:homme}"}
```

| Key | Type | Default | Meaning |
|---|---|---|---|
| `ref` | string | | Reference name of the video, declared in `refs`. The file is given by an « H3 Plan - Video » node with that name. |
| `start`, `end` | number (seconds of the file) | `start`: 0 | The edited segment. The timeline of the plan starts with the segment: frame 0 of the timeline is `start`. The clips that end before `end` edit the video; the next ones continue it (see below). |
| `instruction` | string | | The edit common to the clips. It replaces `{edit}` in their prompts; the pictures it names (`{picture:NAME}`) are added at the end of the references of each clip that uses `{edit}`. |
| `sound` | `"original"` or `"h3"` | `"original"` | Sound of the final video: the original sound of the segment (untouched), or the sound H3 made (to change a voice or a line). |

`free` mode only, and not together with `start_video`. Each clip gets the frames of the file under
its own span of the timeline (from `start` + its raw start, `frames` frames, resized to cover the
picture size and cropped in the middle) as **`<Video 1>`**, with the sound of that span as its
soundtrack, which H3 numbers `<Audio 1>`: the `{voice:NAME}` placeholders are then numbered from
`<Audio 2>`. A clip that edits a video lasts 2 to 15 s (48 to 360 frames), the length H3 takes for a
reference video. A `continue` clip still starts from the end of the previous (edited) clip; a new
scene is best put where the video itself changes shot. The prompt only says what changes, for
example: *An edit of `<Video 1>`: the whole footage becomes a hand-drawn cartoon; framing, motion
and timing as in `<Video 1>`.*

**The common instruction.** When most clips get the same edit, write it once in `instruction` and put
`{edit}` in the prompts: *An edit of `<Video 1>`: {edit}.* A clip can complete it (`{edit}; the man
also wears a red scarf`) or replace it (no `{edit}` in its prompt). Changing the instruction changes
the clips that use it (their takes are stale).

**After the segment.** The clips that end after `end` do not edit the video: they continue it, from the
last edited clip, like any clip (no `<Video 1>` in their prompt: it is an error). In the final video
the original sound (`"sound": "original"`) is kept over the edited part only; the clips after it keep
their own sound.

## 6. Prompt rules

Each `prompt` is one string with exactly these six sections, in this order, each name on its
own line followed by its text:

```
subject_definitions:
summary:
retention_analysis:
detailed_description:
overall_soundscape:
non_diegetic_music:
```

### 6.1 Naming references: placeholders

Refer to the clip's references with **placeholders**; the node turns them into H3's numbered tags
according to what the workflow really provides:

- `{picture:NAME}` becomes `<Picture N>`. Images are numbered in the order of the clip's `refs`,
  counting only the names that have an image. If the workflow has no image named `NAME`, the
  clip stops with an error.
- `{voice:NAME}` becomes `<Audio N>`. Voices are numbered in the order of the clip's `refs`,
  counting only the voices actually used. **Write each `{voice:NAME}` on a line of its own, with
  nothing else that matters on that line**, for example
  `<Subject 1> speaks with the voice from {voice:robot}.` If the workflow has no voice named
  `NAME`, that whole line is removed and H3 chooses a voice for the character. In `music_video`
  mode every `{voice:...}` line is removed.
- Every name used in a placeholder must be in the clip's `refs`.
- Never write `<Audio N>` yourself. In `music_video` mode the song is not a reference asset; in
  `free` mode use `{voice:NAME}`.
- Older plans write `<Picture N>` directly: N is then the N-th name of `refs` that has an image.
  This still works, but do not mix `<Picture N>` and `{picture:NAME}` in one prompt.

### 6.2 Sections

- Write everything in English, except sung or spoken words and visible text, which stay in
  their original language.
- `subject_definitions`: one line per reused element, for example
  `<Subject 1> is the small robot whose body, face and antenna come from {picture:robot}.`
  A place: `The beach, the sea and the sunset come from {picture:beach}.` A voice: its own
  line, as above. An off-screen character (the person holding the camera, a narrator) can be a
  subject with a voice and no picture.
- `summary`: one paragraph starting with `[reference generation]`.
- `retention_analysis`: one line per subject or place with an image, for example
  `<Subject 1> (appears throughout [Shot 1]): fully_preserved - ...`. Markers:
  `fully_preserved`, `partially_preserved`, `attribute_transfer`, `weak_reference`.
- `detailed_description`: one or two style sentences, then `[Shot 1] ...`.
  Words go in `<d>[Language] words</d>`, attached to their speaker as `<Subject N> (S1)`; give
  each speaking character its own speaker number (`(S1)`, `(S2)`, …) and keep it for the whole
  plan. An off-screen speaker: `<Subject 2> (S2), off-screen, says: <d>[French] ...</d>`.
  - `music_video`: put inside `<d>` the words actually heard in the song between the clip's
    `raw_start` and `end`, including the ones that fall in the overlap.
  - `free`: put inside `<d>` only the new lines of this clip, in speaking order, with the tone
    of voice (laughing, whispering, out of breath). Do not repeat what the previous clip said.
- `overall_soundscape`: diegetic sounds (street noise, footsteps, room tone). No lyrics, no lines.
  In `free` mode this is what H3 will make audible: describe it.
- `non_diegetic_music`: `music_video`: describe the current section of the song. No lyrics.
  `free`: normally `None.`
- A `continue: true` clip must first continue what is already happening, then develop it. Start
  its `[Shot 1]` by stating that motion, camera, lighting and environment (and, in `free` mode,
  the sound) continue uninterrupted from the protected context.
- A `continue: false` clip (other than the first) should say that its first second and a half is
  a hidden lead-in and that the scene is established from the first frame.
- If a mouth must be readable, frame it: medium shot or closer, face toward the camera.
- If a character is on screen but does not speak or sing, say so explicitly.

### 6.3 Speech length (`free` mode)

French or English speech runs at about 2.5 words per second. Above 3 words per second of new
picture, H3 rushes or cuts lines; the checker warns. Leave room for reactions and pauses.

## 7. Voices (`free` mode)

- A voice sample is a clean recording of the character's voice, 2 to 15 s, ideally speaking
  the language of the plan, without music or other voices.
- MiniMax H3 accepts at most 3 reference sounds per clip, 15 s in all, and 12 reference files
  in all. When a clip uses several voices, each sample is cut to its first `15 / number of
  voices` seconds (7.5 s for two voices, 5 s for three).
- Only the voices whose `{voice:NAME}` line is in the clip's prompt are sent. A character
  without a voice sample is still allowed to speak: H3 invents a voice, which may change from
  one clip to the next.

## 8. Validation checklist

A plan is valid when all of these hold:

1. It is one JSON object with `version` 1 to 5 and a legal `project`; `mode: "free"` needs version 3 or more.
2. `width` and `height`, when present, are both given and are multiples of 32.
3. Every `frames` is `17k + 5` and greater than `context_frames`; in `free` mode `context_frames`
   is 39, 90, 141, 192 or 243.
4. The first clip has `continue: false`.
5. No clip lists a reference twice; all are declared in `refs` when `refs` exists; at most 9
   (`music_video`) or 12 (`free`) per clip.
6. Every placeholder is well formed and names one of the clip's `refs`; at most 9 pictures and 3
   voices per clip; each `{voice:...}` is on its own line; no hand-written `<Audio N>` in `free` mode.
7. No prompt uses `<Picture N>` with N greater than the number of refs of its clip.
8. Clip names are unique.
9. `music_video`: the last clip ends at or before the end of the song. `free`: there is no `song`.
10. `dialogue` speakers are names of the clip's `refs`.

Run `python plan_tool.py check my_plan.json [--song-duration 99.4]` to verify a plan and print
its timing table.

## 9. Minimal examples

### 9.1 `music_video`

```json
{
  "version": 6,
  "project": "demo",
  "mode": "music_video",
  "refs": {
    "singer": "image: the singer, full body, with the outfit she wears in the video",
    "street": "image: the cobbled street at night, empty"
  },
  "song": { "file": "demo.mp3", "duration_seconds": 14.0 },
  "clips": [
    {
      "name": "street_a",
      "frames": 209,
      "continue": false,
      "refs": ["singer", "street"],
      "lyrics": "First line of the song,",
      "prompt": "subject_definitions:\n<Subject 1> is the singer whose face, hair and clothing come from {picture:singer}.\n<Subject 2> is the street whose architecture and lighting come from {picture:street}.\n\nsummary:\n[reference generation] <Subject 1> walks down <Subject 2> at night and starts singing.\n\nretention_analysis:\n<Subject 1> (appears throughout [Shot 1]): fully_preserved - face, hair and clothing are kept while pose and lighting follow the scene.\n<Subject 2> (appears throughout [Shot 1]): fully_preserved - architecture and lighting are kept.\n\ndetailed_description:\nThe target video is a cinematic night-time music video with soft practical lighting.\n[Shot 1] A medium tracking shot. <Subject 1> walks toward the camera along <Subject 2>. <Subject 1> (S1) sings with clearly readable mouth articulation: <d>[English] First line of the song,</d> End with the walk and the camera still moving.\n\noverall_soundscape:\nQuiet footsteps beneath the song.\n\nnon_diegetic_music:\nThe opening verse of the original song, a solo voice over a soft guitar."
    },
    {
      "name": "street_b",
      "frames": 158,
      "continue": true,
      "refs": ["singer", "street"],
      "lyrics": "second line of the song.",
      "prompt": "subject_definitions:\n<Subject 1> is the singer whose face, hair and clothing come from {picture:singer}.\n<Subject 2> is the street whose architecture and lighting come from {picture:street}.\n\nsummary:\n[reference generation] Continue the same unbroken shot: <Subject 1> keeps walking and finishes the phrase.\n\nretention_analysis:\n<Subject 1> (appears throughout [Shot 1]): fully_preserved - identity is kept while pose and lighting follow the incoming continuation state.\n<Subject 2> (appears throughout [Shot 1]): fully_preserved - architecture and lighting are kept.\n\ndetailed_description:\nThe target video is a cinematic night-time music video with soft practical lighting.\n[Shot 1] The incoming walk, camera movement, lighting and environment continue uninterrupted from the protected video context. <Subject 1> (S1) keeps singing: <d>[English] song, second line of the song.</d> She stops under a street lamp and looks up as the camera settles.\n\noverall_soundscape:\nQuiet footsteps that stop beneath the song.\n\nnon_diegetic_music:\nThe opening verse of the original song continues, a solo voice over a soft guitar."
    }
  ]
}
```

Timing: clip 1 covers 0 → 8.708 s. Clip 2 has `raw_start` 170 frames (7.083 s), is visible from
8.708 s and ends at 13.667 s, inside the 14-second song.

### 9.2 `free`

```json
{
  "version": 6,
  "project": "kitchen",
  "mode": "free",
  "refs": {
    "anna": "image and voice: the woman",
    "kitchen": "image: the kitchen"
  },
  "clips": [
    {
      "name": "coffee",
      "frames": 192,
      "refs": ["anna", "kitchen"],
      "dialogue": [{ "speaker": "anna", "text": "Encore en retard ? Le café est froid.", "language": "French" }],
      "prompt": "subject_definitions:\n<Subject 1> is the woman whose face, hair and clothing come from {picture:anna}.\n<Subject 1> speaks with the voice from {voice:anna}.\nThe kitchen, its furniture and light come from {picture:kitchen}.\n\nsummary:\n[reference generation] Morning in the kitchen: <Subject 1> teases someone off-screen who arrives late.\n\nretention_analysis:\n<Subject 1> (appears throughout [Shot 1]): fully_preserved - face, hair and clothing are kept.\nThe kitchen (throughout [Shot 1]): fully_preserved - same furniture and light.\n\ndetailed_description:\nThe target video is a cinematic live-action scene with soft morning light.\n[Shot 1] Medium shot. <Subject 1> leans on the counter, a mug in her hand, and looks toward the door with a raised eyebrow. <Subject 1> (S1), amused, says: <d>[French] Encore en retard ? Le café est froid.</d> She takes a sip, smiling. End with a quiet half second.\n\noverall_soundscape:\nQuiet kitchen: a fridge humming, a clock ticking, the mug set down on the counter.\n\nnon_diegetic_music:\nNone."
    }
  ]
}
```

If the workflow has no voice node named `anna`, the line `<Subject 1> speaks with the voice from
{voice:anna}.` is dropped and H3 chooses her voice.
